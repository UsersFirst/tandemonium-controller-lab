# UI design system — controller lab + Tandemonium

_2026-10-18 · Status: **kit 0.2 + every lab page + the game's buttons, lobby navigation and Room step are on the system** (lab PRs #116 #118 #119 merged, tags `ui-v0.1.0` / `ui-v0.2.0`; game #411 merged, #413 + Room PR open for playtest). §4 lists what shipped and what is next._

## 0. The problem, named

Pete's struggle with UI components and navigation flow in both repos came down to four questions:

| # | question | answer |
|---|---|---|
| 1 | Can I **reuse strongly typed custom controls** across the lab and the game? | Yes: `@usersfirst/ui`, a typed custom-element base with no build step (D1 + D2) |
| 2 | Should these be **Web Components**? | Yes, native, light DOM (D1) |
| 3 | Do I need a **full design system**? | Tokens → primitives → patterns → screens, with a living gallery as the source of truth (D3) |
| 4 | Why is **navigation flow** so hard to keep straight (#167, #173, #318, #346)? | Screen state had no single owner; `uf-flow` is that owner (D4) |

The common root: every screen's state was imperative JS (`style.display =`, `classList.toggle('visible')`) spread across two monoliths and one 6,500-line HTML file, so there was nothing reusable to build against.

Buttons were the biggest single duplication: 23 button-ish classes in the game, four more in the lab.

## 2. Constraints the design honours

1. **No bundler, ever.** The game deploys by rsync of the committed tree and Electron loads ESM from `file://` (#318). Everything is raw ESM + CSS a browser loads directly.
2. **The lab owns shared UI; the game vendors it.** Same mechanism as `@usersfirst/controller-core`: `scripts/sync-ui.js` + `scripts/check-ui.js` drift guard + `shared/ui/UI_VERSION.json` stamp, pinned to the lab commit.
3. **Light DOM by default.** The game's `FocusController`, its page CSS, its puppeteer smoke tests and the capture tool all reach into elements with ordinary selectors. Shadow DOM is opt-in per leaf widget (none use it yet).
4. **The game's existing code must keep working unchanged.** It writes `textContent`/`innerHTML` onto buttons, toggles classes, reads `.disabled`, calls `.click()`. So the host element *is* the button: no inner `<button>` to wipe.
5. **Design decisions are Pete's.** The seeded tokens are the dominant values already in the game, so adopting the kit changes nothing a player sees; re-skinning is a later, one-file edit.

## 3. Decisions

### D1 · Native custom elements on a small typed base class

`packages/ui/src/uf-element.js` → `UfElement`: static `tag`, static typed `props` (string / number / boolean / enum with defaults), attribute ↔ property reflection with coercion (a typo'd enum degrades to the default and warns, never throws), batched microtask DOM pass, `update(changed)` fast path, `render()` returning `null` to **keep authored children** (so ids, listeners and references captured by the host page survive the upgrade), `emit()`, token-only `styles` injected once per tag.

Why not Lit / Preact / React: all want a build or a CDN import. Lit is the only raw-ESM-friendly option and could be adopted *later* under the same `uf-*` tags if templating pain shows up.

### D2 · Typing: JSDoc + `// @ts-check` + `tsc --noEmit`, no emitted code

`packages/ui/tsconfig.json` (`checkJs`, `strict`, `noImplicitOverride`, `lib: DOM`), `npm run typecheck`, run in CI. Each element declares explicit typed getters/setters per prop (generated by the scaffolder), and `src/elements.d.ts` maps tag → class so `document.createElement('uf-button').variant` is `'primary' | 'accent' | 'ghost' | 'danger' | 'versus'` in any editor — in the game too, since `elements.d.ts` is vendored. TypeScript *source* was rejected only because it would mean committing emitted JS or adding a build step.

### D3 · Tokens → primitives → patterns → screens; the gallery is the source of truth

- **Tokens** (`packages/ui/src/tokens.css`): the only file where a colour, size, radius, z-index or duration is a literal. Seeded from the audit's dominant values; where the two repos disagreed the game's value won. Semantic names (`--uf-color-accent`, `-soft` fills, `-line` borders), one TV-scale media query instead of per-rule overrides.
- **Primitives** (light DOM): `uf-button` (the one button; host is the button; `variant`, `size`, `disabled`, `selected`, optional `label`), `uf-chip` (status tags), `uf-seat` (lobby seat; owns its DOM), `uf-step` (a screen: prompt + authored content + hint), `uf-flow` (hosts steps; exactly one active; `go()` / `back()` / history; `data-flow-go` / `data-flow-back` wiring; `uf-flow:change` event).
- **Gallery** (`packages/ui/gallery.html`): every token and every element in every state; captured by the screenboard at phone / desktop / TV.
- **Scaffolder** (`npm run ui:new-element -- uf-x --props "…"`): one command creates the element file with typed accessors, exports it, types the tag, adds a gallery section and a capture screen. The pattern is never hand-copied.

### D4 · Navigation: one owner of "current screen"

`uf-flow` replaces the lab's `showScreen()` today and is the target for the game's `_showStep()` (§4 phase 3). Side effects a screen needs on entry/exit (start a monitor, clear input edges) hang off the `uf-flow:change` event, not off the navigation code.

## 4. What shipped and what is next

### Shipped — lab PR (`feat/ui-design-system`)
- `packages/ui` (`@usersfirst/ui` 0.0.1): base class, tokens, five elements, gallery, `elements.d.ts`, typecheck, node:test suite, scaffolder. CI job `ui` runs typecheck + tests.
- `apps/overlay/src/lobby.html` + `js/lobby-app.js` rebuilt on the kit: `uf-flow` owns the three steps, mode buttons / CTAs / back / pair buttons are `uf-button`, seats are `uf-seat` driven from state, controller-panel tags are `uf-chip`; page CSS reads tokens through aliases. `copy-workspace.js` vendors the kit into `apps/overlay/src/lib/ui/` like the other packages.
- Tooling: `npm run ui:audit` (the scoreboard), `npm run ui:screenboard -- --manifest tandemonium|lab-overlay|ui-gallery [--root …] [--screens …] [--debug]` (visual regression captures).
- Not migrated yet: `index.html`, `multi.html` and the detached HUD windows in the overlay app (screen by screen, same recipe as `lobby.html`).

### Shipped — lab kit 0.2 (`feat/ui-kit-0.2`, UsersFirst/tandemonium-controller-lab#117)
- **FocusController in the kit** (`packages/ui/src/focus-controller.js`, lifted from the game's `js/nav/focus-controller.js` with types, behaviour unchanged) plus `inputs.js` (`GamepadInput`, `ManualInput`). `uf-step.focusables()` lists a screen's navigable items; `uf-flow.attachFocus(controller)` makes the active step the controller's spatial scope on every change, and `refreshFocus()` re-reads it. One controller-navigation engine for both repos.
- **Browser tests** (`packages/ui/test/browser.test.mjs`): headless Chrome over `gallery.html` — reflection, enum fallback, disabled/keyboard/click suppression, flow go/back/history/events/data-flow wiring, focusables + FocusController driving a flow. Found two real bugs on first run (a11y attributes lagging the property; attribute-driven navigation not applying). Skips when no puppeteer; CI installs it.
- **Published style guide**: `scripts/build-web.js` copies the kit to `/ui/` (gallery at `/ui/gallery.html`) and the inventory to `/design-system/` on lab.housetandem.com; linked from the landing page.
- **Audit ratchet**: `npm run ui:audit -- --check` fails when a metric exceeds `design/audit/thresholds.json`; CI runs it for the lab target. Lower the numbers as they fall.
- Kit version 0.2.0 → tag `ui-v0.2.0` on merge.

### Shipped — game PR (`feat/ui-design-system`)
- `shared/ui/` vendored (`npm run sync-ui`, `npm run check:ui`, `UI_VERSION.json`), loaded from `index.html` before the page CSS (`tokens.css`) and before `js/game.js` (`index.js`).
- All 45 static `<button class="lobby-btn …">` are `<uf-button>` (accent/versus modifiers became `variant`); the JS-built lobby buttons in `slingshot-ui.js` and `versus-hud.js` too. The `.lobby-btn` / `-accent` / `-versus` CSS is gone; remaining modifier classes (`.cta-btn`, `.lobby-btn-p2-*`, `.role-locked`) stay on the hosts and read tokens.
- Class toggles that carried state (`classList.add('lobby-btn-accent')`) are typed props (`btn.variant = 'accent'`).
- Dominant literals in the page CSS are tokens: accent green (40 sites), gold (26), danger red (7), surface (3), the font stack (20), and the four pre-existing page variables alias the tokens.
- Smoke scripts count `uf-button` alongside `button`. Unit tests (411), lobby smoke, end-screen layout check and the ride/crash/slingshot/CTA/tutorial/economy smokes pass.
